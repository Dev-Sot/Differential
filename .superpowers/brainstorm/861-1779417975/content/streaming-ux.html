¿Cómo debe funcionar el streaming?

El agente ReAct tiene dos partes: el razonamiento interno (Thought/Action/Observation) y la respuesta final. ¿Qué transmitimos en tiempo real?

A

Solo la respuesta final

El agente piensa internamente (invisible). Cuando termina, los tokens de la respuesta final aparecen palabra por palabra.

Preview
Tengo fiebre y dolor muscular
🤖 Analizando...
Condición principal sugerida: Síndrome gripal
Nivel de urgencia: Moderada
Fundamento: Según Harrison (p.301), la combinación de fie
Pros
Más simple · Respuesta limpia · Menos tokens de UI
Contras
El usuario no sabe que está pasando durante el razonamiento (20-30s de espera)
B

Razonamiento en vivo + respuesta

Los pasos ReAct (Thought, Tool calls, Observations) aparecen en tiempo real mientras el agente trabaja. Luego la respuesta final.

Preview
Tengo fiebre y dolor muscular
💭 Pensando: Buscaré síntomas de fiebre con dolor muscular...
⚙ Llamando: search_symptoms("fiebre dolor muscular")
Pros
El usuario ve el progreso · Sensación de transparencia · No hay "pantalla negra"
Contras
Más complejo de implementar · La UI actual debe refactorizarse para updates incrementales
